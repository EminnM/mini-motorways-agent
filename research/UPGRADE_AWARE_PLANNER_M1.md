## Stage A — interface and opportunity validation: **pass**
* Plugin: `BuildPolicyObservation` now emits `globals.pendingUpgradeTypes` = `[{type, amount, additionalConcrete}, …]` for the first pending choice, in slot order (`UpgradeDatabaseModel.pendingUpgradeChoices[0].choices[i]`, the same list `ChooseUpgrade(i)` selects from). Existing keys, the Python encoder (ignores unknown globals) and the action masks are unchanged; normal-path observations equal the pre-patch S22 log with the new key removed (150 decisions, only the known transient at 127). Build v5 deployed (sha 72503023…, backups and hashes in `research/spawn_harness/backup/SHA256.txt`).
* Reliability: 75 choices in 36 episodes; the export always listed exactly 2 options; the type reported by the game's `applyInfo` after `ChooseUpgrade` matched the exported type of the chosen slot **75/75**; inventory totals moved by exactly `amount` of the chosen type and by `additionalConcrete` of concrete on every sampled choice.
* Frequency and content: choices occur at decisions 141, 281, 421, 561 (weekly); 2.08 per episode (episodes ending at ~150 see one). Offered pairs: TrafficLight|Roundabout 36 (always week 1), Bridge|TrafficLight 18, Concrete|TrafficLight 9, Motorway|Roundabout 6, Bridge|Motorway 3, Concrete|Roundabout 2, Bridge|Concrete 1. The two options always differed. **Every package carries `additionalConcrete` (20, 20, 10, 20 by week) regardless of type** — this is the source of the weekly concrete top-ups seen since S12; the choice decides only the infrastructure item.

## Interpretation
Policy-level outcome: **the upgrade choice has no measurable effect on this agent's native play**. Mechanistic reading, consistent with S25/S29 and not a causal claim about individual choices: concrete arrives with every package, so the choice never changes the only resource planner B consumes; the agent cannot place traffic lights, roundabouts or motorways, so those items are inert; bridges (available 1 from the start, +1 when chosen) were never the binding constraint on these seeds. The rule and the random arm differ from slot0 only in which inert item is stocked.

## Decision: **reject upgrade-aware selection for the current agent.** 
The export stays (read-only, validated, useful later), but no rule or learned selector should be built on it until the agent can act on what it selects. The specifically justified next capability — if the native-strategy objective is to continue — is therefore an **infrastructure action family** (M2 in S29: motorway placement first, since it alone changes travel time; roundabouts/lights only matter in dense junction networks per S25), *gated* by the open question whether trip time affects deliveries at ≤ 1 house per destination (S28 → needs the per-destination delivery/path-cost telemetry). Absent that, this regime offers planner B no remaining decision where upgrades, road topology or spawn placement change the outcome, and the learned-strategy objective would need a different map/regime (denser cities, longer horizons) to have something to learn. Nothing further was started.
